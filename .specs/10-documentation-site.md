# 10 — Documentation site

**Status:** implemented. Code: `web/src/docsite/` (`DocsSite.jsx`, `md.jsx`, `nav.js`, `docsite.css`, `pages/*.md`), route chosen in `web/src/main.jsx`.

A Docusaurus-style layout: top bar, collapsible sidebar tree, content with a *Next / Previous* pager and an *On this page* index.

## Behaviour

- Public: `/docs` and `/docs/<slug>` need no login and use no API. The SPA fallback of the server serves them; `main.jsx` loads the docs bundle (own CSS, no React Flow) instead of the app for those paths.
- **Top bar**: brand, *Docs*, *Go to the app*, search (`Ctrl/⌘+K`), light/dark toggle (follows the app theme the first time, then remembered in `localStorage['ds-theme']`), *Open app*.
- **Sidebar**: `NAV` in `nav.js` (pages and collapsible sections; the section of the open page is expanded). Burger menu on narrow screens.
- **Search**: client side over titles and body text, ranked by title match then number of mentions; Enter opens the first result.
- **Page**: title, Markdown body, right-hand *On this page* (h2/h3, the heading being read is highlighted), pager. Internal links (`[x](slug)`, `[x](slug#anchor)`) keep the single-page navigation; browser back/forward work.
- **Markdown subset** (`md.jsx`, no dependency): `#`–`###`, paragraphs, lists, tables, fenced code (language label + Copy button), `> **Note|Tip|Warning|Info|Important** text` callouts, rules, inline code / bold / italic / links.
- The app links to it from **More → Documentation** (new tab). The old in-app Help drawer was removed.

## Content

One `.md` file per page, first line `# Title`. The page order is `NAV` in `web/src/docsite/nav.js` (25 pages: introduction, getting started, syntax, database import and security, shared connections, diagram basics, Tables panel, arrange, table groups, data lineage, generated documentation, import/export, accounts and sharing, share links, versions and history, administration, self-hosting, hosting requirements, connect Claude (MCP), license, shortcuts and FAQ, release notes). **Update the page in the same change as the behaviour** (see [AGENTS.md](../AGENTS.md)).

- [x] Search finds a page by title and by body text; Ctrl+K opens it, Esc closes it.

- [x] **More → Documentation** opens `/docs` in a new tab.

## Known limitations and follow-ups

- **Text proofread once** against the UI labels, shortcuts, limits and server code. Behaviour that is only described (not clicked through) can still drift; re-check a page when its feature changes.
- **Screenshots only, no GIFs/video** (heavy and choppy). Nineteen JPEGs of the sample model and the demo PostgreSQL are in `web/src/docsite/img/` and used with `![caption](file.jpg)` (resolved by `md.jsx`). They are generated by `tools/docshots.mjs` (headless Chrome against a throw-away instance with fictional accounts): rerun it when a screen changes, then look at every picture. **Never capture real connections, other people's diagrams (the admin Diagrams list shows owner names) or personal data.** Pages without a picture yet: Share links, Relationships, Table groups (only the picker), Import & export, the member's view of a shared connection. Retake the pictures when a screen changes (the last round added lineage with a note and presence, History, the Docs changelog and the Administration Connections / Audit log tabs).
- Code blocks: `dbml` blocks are coloured with the editor's tokenizer (`dbml` exported from `Editor.jsx`, `.tok-*` colours in `docsite.css`); other languages are plain.
- **Narrow screens**: the burger/sidebar layout was checked at 375 px emulated (`tools/uiaudit.mjs`), not on a real phone. Print styles are missing.
- The `release-notes` page is written by hand: a `## X.Y.Z` section per release (with its *Not tested* list), above the changes grouped by theme ([`RELEASING.md`](../RELEASING.md)). There is no API tab; `server/src/index.js` is the route reference.
- **Keep it current**: every behaviour change updates its page in the same commit (rule in `AGENTS.md`).
