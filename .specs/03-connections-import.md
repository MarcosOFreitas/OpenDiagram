# 03 — Connections & live import

**Status:** implemented. Oracle TLS `verify` verified by hand against an OCI Autonomous DB, and `verify` / `serverDn` / `noverify` verified by `server/test-oracle-tls.mjs` against a TLS proxy; wallets are not supported. Code: `server/src/{index,introspect,store,dbml}.js`, drawer *Database* tab in `web/src/App.jsx`.

## Connection model

Stored per account in the SQLite `connections` table (`DATA_DIR/app.db`); other accounts cannot list or use them ([09](09-accounts-sharing.md)):

| Field | Notes |
|-------|-------|
| `id`, `name`, `type` (`postgres`\|`oracle`\|`mysql`), `host`, `port`, `database` (Oracle: service name; MySQL: optional, it only sets the session default: a MySQL database is a schema), `user` | |
| `password`, `caPem` | **secrets**, AES-256-GCM with `APP_SECRET`. On save: empty/undefined keeps stored value, `null` clears. Never returned by the API (`hasCa` flag instead). |
| `tls` | `off` \| `verify` (chain + host name; optional `caPem`) \| `noverify` (PG: no certificate check; Oracle: skips DN/host match, chain still validated). Legacy `ssl:true` ⇒ `noverify`. |
| `serverDn` | Oracle `SSL_SERVER_CERT_DN` (optional, with `verify`). |
| `blockWritable` | strict guardrail (below). |
| `schemas`, `tables` | last import selection (used by refresh). |
| `refreshMinutes` | 0 = manual only. |

## Guardrails

1. **Read-only session (always).** MySQL 8.0+ (MariaDB 10.6+ best effort): `SET SESSION TRANSACTION READ ONLY`, `max_execution_time` 30 s, then `START TRANSACTION READ ONLY` … `ROLLBACK`; `connectTimeout` 8 s; the driver runs with `disableEval` and without the `LOCAL_FILES` capability (a rogue server, see [05](05-security.md)). Postgres: startup options `default_transaction_read_only=on`, `statement_timeout=30s`, `idle_in_transaction_session_timeout=60s`, then `BEGIN READ ONLY` … `ROLLBACK`. Oracle: `SET TRANSACTION READ ONLY`, `callTimeout=30s`. Only catalog/dictionary views are queried — never user tables.
2. **Privilege check (Test and Import).** Returns warnings, never blocks unless `blockWritable`:
   - Postgres: superuser, createrole, createdb, bypassrls; `has_table_privilege(INSERT,UPDATE,DELETE,TRUNCATE)` on any table of the selected schemas; `CREATE` on those schemas.
   - MySQL: an allowlist over `SHOW GRANTS FOR CURRENT_USER() USING` the active roles (`SHOW GRANTS` on MariaDB): anything but `USAGE`, `SELECT`, `SHOW VIEW`, `SHOW DATABASES` on `*.*`, a selected database (LIKE patterns included) or its tables, and `WITH GRANT OPTION`, is a warning naming the privileges and the scope (`EXECUTE` included).
   - Oracle: `DBA`/`RESOURCE` roles; system privileges beyond read (`… ANY`, `CREATE TABLE/VIEW/PROCEDURE/SEQUENCE/TRIGGER`, `UNLIMITED TABLESPACE`); `INSERT/UPDATE/DELETE` grants on selected schemas (`ALL_TAB_PRIVS_RECD`); user is the owner of a selected schema.
   - If the check itself fails ⇒ a warning `could not verify privileges (…)`.
3. **Strict mode.** With `blockWritable`, `/api/import` answers `403 Blocked by guardrail: …` when warnings exist.

## What is imported

Tables (`pg_class` kinds `r`,`p` / `ALL_TABLES` excluding nested, secondary and `BIN$`), table + column comments, columns (type via `format_type` / Oracle type formatting, nullability, default expression), PK (single → `[pk]`, composite → `indexes { (a,b) [pk] }`), FK (single/composite, `ON DELETE`/`ON UPDATE` (Oracle: `ON DELETE` only)), non-PK indexes (unique flag, method, expression columns). FKs to tables outside the selection are dropped. Optional `tables` filter (case-insensitive; plain `name` or `schema.name` — the UI picker stores `schema.name`).
Also (A1), with the DBML representation in [04](04-formats.md#objects-without-a-dbml-type):
- **Views** (Postgres `v`, `m`; Oracle `ALL_VIEWS` + `ALL_MVIEWS`) with columns, comment and, optionally, the DDL that builds them. The definition (`pg_get_viewdef`, `TEXT_VC` / `ALL_MVIEWS.QUERY`) is always read, because the column lineage is parsed from it, but it only reaches the DBML when the request has `ddl: true` (UI: *Full DDL of views* in the table picker, off by default): then the note holds `VIEW` / `MATERIALIZED VIEW` + `CREATE [MATERIALIZED] VIEW schema.name AS <definition>;`, otherwise only the marker line. The choice is stored in the diagram's `source` (`source.ddl`) so a refresh repeats it. In Oracle a materialized view also exists in `ALL_TABLES` as a container table of the same name: it is listed once, as a materialized view (`MLOG$_`/`RUPD$_` helper tables and the internal `I_SNAP$_` index are skipped).
- **Enums** (Postgres `pg_enum`; Oracle has none), **sequences** (`pg_sequence` / `ALL_SEQUENCES`; sequences owned by a column — serial/identity, `ISEQ$$_` — are skipped; the **users** of a sequence are read too: PostgreSQL `pg_depend` from the column default `pg_attrdef` to the sequence, giving table and column; Oracle `ALL_DEPENDENCIES` of type TRIGGER (mapped to the trigger's table) or TABLE on the sequence; `assemble(..., seqUse)` keeps only tables of the import and `toDbml` writes a `SEQUENCES` section in the note of each using table, a sequence used by nothing imported stays a standalone Note; sequences used only inside functions are not linked), **triggers** (`pg_trigger` non-internal + `pg_get_triggerdef`; Oracle `ALL_TRIGGERS` timing/event/status, no body). Functions/procedures and comments on them are not imported.
- The `tables` filter and the picker (`/api/tables` returns `view: true|false`) also apply to views.
- TableGroups from the picker: *Groups* tab (name, color from the editor palette or any color, each group has its own table chooser (search, select shown) independent of the import selection; a table belongs to one group, and adding it to another group moves it (the chooser marks tables already grouped)); groups start from the diagram's current TableGroups; on **Import** they are appended as `TableGroup` blocks (members not imported are dropped, tables put in a group are ticked for the import right away in the Tables tab, unless nothing is ticked, which already means all). A new Import also re-applies the diagram's current groups (before, only Refresh kept them).
- Picker UI: a centered dialog (`TablePicker.jsx`) with search (plain text, `*`/`?` wildcards like `VW_*`, or `/regex/`), schema and tables/views filters, "selected only", select/clear shown; Esc or Cancel discards, "Use N tables" applies; nothing selected = all tables.

**MySQL:** the schemas are the databases the account can see (without `mysql`, `sys`, `information_schema`, `performance_schema`); tables and views from `information_schema.TABLES` (a view's `TABLE_COMMENT` `VIEW` is not a comment), columns with the type as MySQL writes it (`int unsigned`), `AUTO_INCREMENT` -> `[increment]`, string defaults quoted, `DEFAULT_GENERATED` ones as expressions, each `enum(...)` column -> a DBML `Enum schema.table_column`, PK, FK with actions, indexes (expression indexes as `(expr)`), triggers in the table note (MySQL shows them only to an account with the `TRIGGER` privilege, so not to a read-only one), view lineage from `VIEW_TABLE_USAGE` (MySQL 8.0.13+) and from the view text read with backticks as double quotes. MariaDB: `max_statement_time` (seconds) instead of `max_execution_time`, no functional indexes (`EXPRESSION`), `COLUMN_DEFAULT` with literals already quoted and `NULL` as text (detected through `VERSION()`), no `VIEW_TABLE_USAGE`.

**Check constraints and partitioning** (item 7b of [14](14-release-v1.md)), all three engines: `assemble(..., checkRows)` hangs `{ name, expr }` on each table and a table row may carry `partition` (method and key); `toDbml` writes a table `checks { `expr` [name: '...'] }` block (always the table form: a column `[check: ...]` has no name) and a `PARTITIONED BY <method> (<key>)` line in the table note, after the comment. Sources: PostgreSQL `pg_constraint` `contype = 'c'` with `pg_get_expr` (a domain's check has `conrelid = 0` and stays out) and `pg_get_partkeydef` for `relkind = 'p'`; partitions (`relispartition`) are left out of the import and of the picker (decision of the author, 2026-10-22: they repeat the parent), and `filterModel` never reports one named in a stored selection as missing (`m.partitions`); Oracle `ALL_CONSTRAINTS` `C` + `ENABLED`, `SEARCH_CONDITION_VC`, without the system `"COL" IS NOT NULL` form (`oraNotNull`), and `ALL_PART_TABLES` + `ALL_PART_KEY_COLUMNS` (no subpartitioning); MySQL `TABLE_CONSTRAINTS` (`ENFORCED = 'YES'`) joined with `CHECK_CONSTRAINTS` (MariaDB: `CHECK_CONSTRAINTS` alone, it has `TABLE_NAME`), nothing before 8.0.16, and `PARTITIONS`; `myExpr` turns a MySQL expression into plain SQL (backticks off plain names, charset introducers `_utf8mb4'x'` off, the outer parentheses off, and MySQL 8.4's escaped quotes `'` in `CHECK_CLAUSE` undone). The docs list the checks under **Checks** (the table ones with their name, a hand-written column check named after its column).

**Columns, all engines** (audit [15](15-audit-2026-10-22.md) Q2-Q4): `pgColumn` / `oraColumn` / `myColumn` map one catalog row each. `increment` for PostgreSQL identity (`attidentity` `a`/`d`) and serial (a `nextval` default on a sequence the column owns: `pg_depend` `a`/`i`, the default is dropped), Oracle `IDENTITY_COLUMN` (the `ISEQ$$` default dropped) and MySQL `AUTO_INCREMENT`. A generated column (PostgreSQL `attgenerated = 's'`, read through `to_jsonb` so an 11 still answers; Oracle `VIRTUAL_COLUMN`; MySQL `VIRTUAL|STORED GENERATED` + `GENERATION_EXPRESSION` through `myExpr`) has no default and its note ends with `GENERATED ALWAYS AS (<expr>) STORED|VIRTUAL` (one pair of enclosing parentheses removed, `unwrap`). A PostgreSQL partial index carries `where` (`pg_get_expr(indpred)`) written as the index note `WHERE ...`; a partial unique index on the primary-key columns is kept (it is not the key). Not changed after measuring (Q1): the Oracle column query's `all_tables` / `all_views` sub-select without an owner filter (154 ms before, 169 ms with the filter, median of 7, on the demo with 2,040 visible tables and views).

**Errors:** a driver error goes through `explainDbError` (`introspect.js`) on every exported call (test, tables, import, privileges, scheduled refresh): plain words for the common cases (`ENOTFOUND`, `ECONNREFUSED` / `NJS-503`, timeouts / `NJS-510`, wrong credentials `28P01` / `ER_ACCESS_DENIED_ERROR` / `ORA-01017`, `pg_hba` / host not allowed, unknown database `3D000` / `ER_BAD_DB_ERROR`, unknown Oracle service `NJS-518` / `ORA-12514`, locked Oracle account, certificate codes, TLS not offered) followed by the driver's first line in brackets, and status 502. Any other error without a status is answered `internal error (request <id>)`, its text only in the server log (`errorReply` in `index.js`).

**Not imported:** functions/procedures, partition bounds and subpartitioning, Oracle enums-by-check.

## Refresh

- Import links the saved connection + selection to the diagram (`diagrams.source` on the server). Top-bar `↻` or drawer *Refresh now* re-imports.
- Auto (server, `refresh.js`): every minute the server picks the diagrams linked to a connection with `refreshMinutes` (minimum 5; older 1-minute settings are raised) whose last run + interval + a per-diagram jitter (0-59 s) has passed, and refreshes them one at a time **as the diagram's owner** (same `resolve`, privilege check and `blockWritable` guardrail as a manual refresh; a shared connection also needs the owner's access). A diagram someone is editing (presence) is skipped until the next minute. The result is merged with `keepGroups` (`merge.js`, a copy of the browser's) and saved with the `baseVersion` it read (a conflict is simply retried) as a history entry "Refresh from database" by "Scheduled refresh", whose summary says what changed in the structure (`structural` in `merge.js`, the words of History → Compare: "1 table added, 2 tables changed"; the line summary when nothing structural changed); the audit detail says the same. The server reads DBML with `dbmlParse.js` (`@dbml/parse` and the model, a few MB once loaded; never `@dbml/core`'s `Parser`, about 300 MB), loaded on the first refresh or agent save. `source.gen` (hash of the last generated DBML) makes an unchanged database a no-op so manual edits stay; a link without it only records the baseline once. State per diagram in `refresh_state` (last run, last error, failures; 5 in a row pause it; a manual refresh that works lifts the pause); the owner gets it as `refresh` in `GET /api/diagrams/:id`. Shared connections: each run is audited as `connection.refresh` (`scheduled: ...`). The browser has no timer any more.
- Compare to last generated DBML (`source.gen`, a hash saved with the link; the old `localStorage.gen:<diagramId>` is still read): identical ⇒ "Already up to date", editor untouched. Changed ⇒ DBML replaced, **TableGroups re-appended** (members that no longer exist are dropped), positions kept by table id, toast shows `+N tables, −N tables, N changed`.
- Other manual edits to imported tables are overwritten (documented in the UI), except hand-written `// lineage:` lines (kept; the generated `// lineage(auto):` ones are rewritten).
- Lineage: `assemble(..., lineage)` -> `{ lineage: [{ target, sources: [{ schema, name, columns }] }] }`, written by `toDbml` as `// lineage(auto): target <- source(col, ...)`. PostgreSQL: `pg_depend` rows of the view's `pg_rewrite` rule (`refobjsubid` gives the columns used; the output-column mapping is not in the catalog). Oracle: `ALL_DEPENDENCIES` (views and materialized views onto tables/views, table level only). Only sources and targets that are part of the import are kept (`importModel` filters them with the picked tables).
- Column lineage (`server/src/lineage.js`, `viewColumnLineage`): the view's SQL (`pg_get_viewdef`, Oracle `ALL_VIEWS.TEXT_VC` / `ALL_MVIEWS.QUERY`) is parsed with `pgsql-ast-parser` (PostgreSQL grammar; it also reads most Oracle queries) and every output column is resolved to the base columns it comes from, through aliases, expressions, `*`, FROM sub-selects, CTEs, UNION, scalar sub-selects and views over views (catalog = the tables of the import). Unreadable SQL (parse error, `(+)`, `CONNECT BY`, over 20,000 characters, `*` over a table outside the import) gives no mapping; a time budget of 8 s per import stops a huge schema from stalling it. Only the SQL text is read, never table data. Written by `toDbml` as `// lineage(auto): schema.view.column <- schema.table.column, ...`. Checked by `node server/test-lineage.mjs` and by `test-guardrails.mjs` against the demo views.

## API

All JSON. Errors: `{error}` with HTTP status.

| Method & path | Body → response |
|---------------|-----------------|
| `GET /api/health` | → `{ok:true}` |
| `GET /api/connections` | → connection list without secrets |
| `POST /api/connections` | connection fields (+ optional `id` to edit) → `{id}` |
| `DELETE /api/connections/:id` | → `{ok:true}` |
| Diagrams, share links, comments | see [09](09-accounts-sharing.md) |
| `POST /api/schemas` | `{id}` or draft fields (draft overrides saved) → `{schemas, warnings, readOnly:true}` |
| `POST /api/tables` | `{id\|draft, schemas[]}` → `{tables:[{schema,name,view}]}` (catalog query, read-only session; feeds the table picker); `400` no schema |
| `POST /api/import` | `{id\|draft, schemas[], tables?[], ddl?: true}` → `{dbml, tables, refs, warnings, at}`; `400` no schema; `403` strict block |
