# 02 — Editor & diagram

**Status:** implemented. Code: `web/src/App.jsx`, `web/src/Editor.jsx`. The documentation site is specified in [10](10-documentation-site.md).

## Behaviour

- **Layout:** top bar (title + save state, Diagram/Docs switch, refresh button when linked, **Share** and **Export** buttons, a **More** menu with Diagrams / Database / Import / View / Documentation (a link to `/docs`), and an avatar menu with Account, Administration (admins) and Sign out; the drawer shows the title of the open section) · collapsible DBML editor · canvas · right drawer (350 px, Esc closes) · floating dock (zoom, fit, arrange).
- **Editor:** CodeMirror 6, dark; **resizable** (drag the edge between editor and diagram, double-click resets; width remembered), optional **line wrapping** (View tab) so no horizontal scrolling is needed; **Ctrl+F / Ctrl+H** opens a find/replace bar at the top with Next/Prev/Select all, Replace/Replace all and Match case / Whole word / Regex toggles, matches highlighted. DBML highlighting (blocks, `[settings]`, types, strings, `` `expr` ``, `#hex`, comments). Autocomplete: block keywords, settings, types, table names, `table.column` (from last valid parse). Parser errors → underline + gutter marker + status bar `line N: message`.
  **Colors:** a swatch widget follows each `headercolor:`/`color:` hex; clicking opens the native color picker and rewrites the hex live. Typing `color: ` / `headercolor: ` opens a 12-color preset list (with swatches).
- **Diagram:** every `Table` is a card (header, PK/FK icons, NN badge, notes as tooltip, indexes rows). Default card width follows the content (min 220, max 480 px): the longest column name always fits; column names are left-aligned and keep priority, types sit on the right and are the first to be cut with an ellipsis (full `name: type` in the row tooltip). `Ref` → edge from child column to parent column, attached to the sides that face each other (every column has handles on both sides; re-chosen while you drag; both on the same side when the tables overlap horizontally), label `child:parent` cardinality. Auto layout with dagre (left→right); compound clusters keep `TableGroup` members together. With TableGroups, Arrange lays out each group on its own (its tables packed inside) and treats it as one block with room for its box, so group boxes never overlap; ungrouped tables are packed as blocks beside them. With 25+ tables and no TableGroups the layout is packed instead (not yet validated on a very large real diagram): each connected component gets its own dagre run (left→right or top→bottom, whichever is closer to 1.6:1), tables without relationships are stacked in balanced columns, and the blocks are packed in rows. Drag keeps positions across edits (by table id). Fit on load/import (not on every keystroke).
- **TableGroup:** `TableGroup name [color: #hex] { tables }` → dashed colored box behind members, follows drags. A table in several groups uses the first.
- **Header color:** `Table t [headercolor: #hex]`.
- **Arrange algorithms** (▾ next to *Arrange*, remembered in the view options): *Auto* (default: packs groups and connected clusters), *Left to right* (plain dagre, groups as clusters), *Pipeline* (stages left→right by dependency: one per TableGroup, or dependency ranks without groups; tables stacked and wrapped), *Snowflake* (most connected table in the center, rings around it), *Compact* (balanced columns, ignores relationships). With groups, Auto/Snowflake/Compact lay out each group on its own so boxes do not overlap. **Highlight relationships** (dock button / View tab): every relationship line turns blue and shows its `Ref` name instead of the cardinality.
- **Tables panel** (header *Tables* button, edge button ‹ on the right of the canvas, `Ctrl/⌘+K`; replaces the old header search): search by table, schema, column or group (plain text, `*`/`?` wildcards, `/regex/`; the canvas dims the non-matching tables), group the list by schema or by TableGroup with visible/total counts, filter (all / visible / hidden, only tables with relationships), eye per table / per group / for the whole list to **hide tables from the diagram** (kept in the saved layout as `layout['@hidden']`, hidden tables leave their relationship lines and group boxes, Arrange only lays out the visible ones), click a row to select and center the table, *target* button = show only this table and the ones related to it, footer chip shows everything again. Highlighted relationships (dock) draw the `Ref` name in a theme-aware pill.
- **Detail level** (View tab): *Full*, *Names* (no types/indexes), *Keys* (only primary/foreign key columns; the others keep their relationship lines on the header) and *Tables* (header only).
- **Saved views** (*Tables* panel, top row): a named view stores which tables are visible, their positions and sizes, line-label offsets, the detail level and the relationship highlight. Switching stores what you were looking at back into the view you leave, so nothing is lost; *Main view* is the state before the first view was saved. Stored in the layout (`@views`, `@base`, `@view`, plus `@detail`/`@hiRefs` of the active view so everybody opening the diagram sees the same thing). Arrange keeps them.
- **Top bar:** title, *Diagram | Docs*, **Share**, **Export** (menu: PNG/SVG, SQL dialects, DBML/JSON, documentation HTML/Markdown, copy DBML) and **More** (Diagrams, Database, Import, View, Help). The Tables panel opens from the edge button on the right of the canvas (a badge shows how many tables are hidden) or `Ctrl/⌘+K`.
- **Focus a group:** clicking or starting to drag a TableGroup title emphasises its box (solid border, glow) and dims the other tables and the lines that do not touch it; click the canvas to clear.
- **Moving things:** drag the title of a TableGroup box to move the whole group (its tables keep their relative positions; saved in the layout). Drag the label of a relationship line to bend the line through the new point (saved in `layout['@labels']`, double-click the label to reset; Arrange resets them).
- **Interactions:** click table → highlights it and its edges; click a relationship line → the line turns orange and only its two tables stay in focus (the rest dims; click the canvas to clear); table header chevron (or double-click the header) collapses/expands a table, dock buttons ⊟/⊞ collapse/expand all (relationship lines stay attached to the header); select a table and drag its edge or corner handles to change width and/or height (a manual height makes the rows scroll; a width-only drag keeps the height automatic); width, height and collapsed state are saved with the layout (`layout['@sizes']` = `{id: {w, h, c}}`); search dims non-matching tables/columns; Arrange re-runs layout in two passes (estimated sizes, then the sizes the browser measured, so manual widths/heights and wrapped text cannot make tables or group boxes overlap); minimap; zoom 5–200 %.
- **View tab:** theme light/dark, background grid on/off, edge style (curved/rounded/step/straight), hide types, hide indexes, snap to grid. Persisted in `localStorage.view`.
- **Templates:** `web/src/templates.js` holds the blank starter and the sample shop model ("Online store - sample": customers, addresses, categories, products, reviews, orders, order_items, payments; 2 enums, composite PK, indexes, 10 refs with actions, 3 colored groups, project note). It is the first diagram of every new account and appears under *Start from a template* in the Diagrams tab. Add more by extending `TEMPLATES`.
- **Documentation:** **More → Documentation** opens `/docs` in a new tab (there is no Help drawer any more; the DBML examples live in the *Syntax* pages with a Copy button).
- **Feedback:** toasts (ok/err), button busy states, empty-state hint.

## Sticky notes
- A top-level DBML `Note name { '''text''' }` is a sticky note (`parsed.notes`: name, text, start/end offsets from `db.notes[].token`). Notes whose text starts with `SEQUENCE ` (the importer's sequences) are not drawn. DBML 3 accepts no settings on a top-level Note, so there is one colour.
- Canvas: node type `note` (`NoteNode`), id `n:<name>`, kept in `nodes` next to the tables, position in the layout root like a table, size in `@sizes`; named views carry the note places; Arrange and collapse-all only touch tables; hidden with `view.notes` (View checkbox, per browser). Double-click edits (textarea, commit on blur, Esc cancels) and rewrites the block in the DBML by offsets (`noteBlock`, triple quotes); the dock button adds `note_N` at the centre of the canvas, in edit mode; the corner ✕ removes the block.
- Not done: note colours (would need a convention outside DBML), Markdown in notes, notes in the Docs view/exports, linking a note to a table.

## Data lineage (`web/src/lineage.js`)
- Syntax (a comment, so DBML parsers ignore it; the editor keeps it as text): `// lineage: target <- source, source(col, col)`; a column on both sides (`v.total <- orders.total`) is a column mapping. Names: `table`, `schema.table`, `table.column`, `schema.table.column`, double quotes for odd names; unknown names are ignored, repeated pairs merged. Import writes `// lineage(auto): ...`; refresh rewrites those and keeps the hand-written ones (`keepGroups` in `App.jsx`).
- Drawing: dashed violet arrows source -> target (type `ref` edge with `data.kind = 'lineage'`, arrow head, table-level handles `ls/lsl/lt/ltr` in the table header; a one-to-one column mapping uses the column handles). Label: `N cols`, the list of columns when the arrow is picked.
- State: `view.lineage` (default on) = dock button + View checkbox; saved per named view (`@lineage`). Hidden tables hide their arrows. Click a table: upstream (violet) / downstream (teal) closure (`closure()`) outlined and its arrows coloured, other lineage arrows fade. Click an arrow: focus it and its two tables. Tables panel: lineage icon per row (show only that table's whole lineage) and the filter "Only tables with data lineage".
- Arrange: while lineage is on, `layout(..., lineage)` appends its edges as pseudo-refs (`lineageRefs`: the derived table is `parent` for dagre so it lands to the right, `child` for the pipeline ranking); Compact ignores them. Docs view and exports: `buildModel(db, lineage)` adds `builtFrom` / `feeds` per table and `model.lineage`; cards show Built from (with columns used) / Feeds, the overview a Data lineage table and a stat. Label: `uses N cols` (the columns a view reads, joins and filters included). A pair of tables with column mappings (`maps`, a column on both sides of a line) is drawn as one arrow per mapped column pair (column handles) instead of the table-level arrow; the Docs view lists the mapping `a -> b`.
- Not done: no UI to draw a lineage link by dragging (decided not to). Column mapping of views comes from the import (spec 03) or from hand-written lines.

## Acceptance criteria

- [x] Typing valid DBML updates the diagram without losing positions of existing tables.
- [x] Invalid DBML shows an underline and a status-bar message with the line; fixing it clears both.
- [x] `TableGroup` renders a colored box around its tables.
- [x] Dark/light and grid toggle apply immediately and persist across reload.
- [x] Click highlights related edges; search dims non-matching tables.
- [x] Swatch click changes the hex in the editor and the diagram color immediately; presets insert a valid hex. (Verified by simulating the picker's `input` events — the OS-native dialog itself was not exercised.)
- [ ] Visual regression coverage — none; UI is verified manually.
- [ ] Narrow-screen/mobile layout — not designed or tested.

## Known gaps

Find/replace shows no "n of m" match counter. No syntax-aware folding, no `Records`/sample-data blocks, no custom properties, no table partials, no side-panel color UI (colors are picked from the swatch next to the hex in the editor).
