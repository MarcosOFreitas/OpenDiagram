# 05 — Security

**Status:** fine for your machine or a trusted network. For **hosting it for other people**, follow the pre-deployment checklist below: every open item there is the operator's to do (HTTPS, the host policy, a rate limit at the proxy). The rules a change must never weaken are the security invariants in [`AGENTS.md`](../AGENTS.md).

## Assets and threats

| Asset | Threat | Mitigation today | Gap |
|-------|--------|------------------|-----|
| Connected databases | Accidental/malicious writes through the app | Read-only sessions; catalog-only queries; privilege warnings; strict block option. PostgreSQL: `BEGIN READ ONLY` + `default_transaction_read_only=on`; Oracle: `SET TRANSACTION READ ONLY`; MySQL/MariaDB: `SET SESSION TRANSACTION READ ONLY` + `START TRANSACTION READ ONLY` ... `ROLLBACK`, `max_execution_time` 30 s, only `information_schema` and `SHOW`; statement timeout 30 s and connect timeout 8 s everywhere. Privilege check by an **allowlist** (MySQL: `USAGE`, `SELECT`, `SHOW VIEW`, `SHOW DATABASES`; anything else, `EXECUTE` included, on the global scope, a selected database or its tables, through active roles too, is a warning). `test-guardrails.mjs` proves a write fails inside the app's own session, as a superuser | None for writes via the app; the credential itself is still powerful if leaked. MySQL `TEMPORARY` tables stay writable in a read-only transaction (the app never sends user SQL) |
| Saved secrets (password, CA PEM) | Disclosure from disk/API | AES-256-GCM at rest keyed by `APP_SECRET`; never returned by the API; `hasCa` flag only; a CA PEM is 64 KB at most | One key, no rotation tool (a new key lists the connections as `secretLost` and asks for their passwords again); a public development key if unset (with a warning; refused in hosted mode, see the checklist) |
| Network position of the server | **SSRF**: any user can make the server connect to any host/port (internal services, metadata endpoints) | `DB_HOST_POLICY` = `open` (default) / `public-only` / `allowlist`, checked by every route that connects or saves a connection; `public-only` refuses private, loopback, link-local, CGNAT, site-local and multicast addresses in any spelling (an IPv4 address written inside IPv6 is checked as IPv4) and pins the address it checked; 8 s connect timeout | `open` is the default (local use); no per-user egress limits |
| API | Unauthorised access to connections/diagrams | e-mail+password accounts (scrypt), roles + administrator-only admin API, sign-up closed by default, forced password change for temporary passwords, server-side sessions in HttpOnly SameSite cookies (list, revoke, length and inactivity limits), 404 for other accounts' resources, CSRF Origin guard (the `Origin` host must equal the request host; with `TRUST_PROXY=1` that host comes from `X-Forwarded-Host`, so a proxy that rewrites `Host` still works; `server/test/proxy.test.js`), all decided on the path of the route that matched (a percent-encoded `/%61pi/...` gets the same checks), persistent sign-in and sign-up throttling, per-person/group/link access levels, last-administrator guard, sign-ins in the audit log | No e-mail verification, MFA or SSO; administrators can reset any password and open/edit/delete any diagram (by design); the audit log does not record reading a diagram |
| Share links | A leaked link grants its level to whoever has it | random 144-bit tokens, per-link level and expiry, instant downgrade/revoke, anonymous = read-only, `no-referrer`, tokens masked in the request log, payload excludes source/credentials; password-protected links are throttled (10 attempts per 15 min per IP and link) | Links are bearer secrets stored in clear in SQLite |
| Oracle connect descriptor | Injection via host/service/DN | whitelist validation (`SAFE`, DN quote/paren rejection) | — |
| Transport | Sniffing / MITM to the DB | TLS modes with certificate verification; a custom CA for PostgreSQL and MySQL | `noverify` allowed (UI warns); Oracle TCPS: `verify`, `serverDn` and `noverify` tested against a TLS proxy and `verify` against OCI; no wallets. MySQL: `off`, `noverify` and a failing `verify` (name mismatch) tested against the server's auto-generated certificate; a `verify` that succeeds with a private CA is not tested |
| Browser | XSS | CSP (`default-src 'self'`, no framing), `nosniff`; React escaping; no `dangerouslySetInnerHTML`; standalone docs HTML is built with `renderToStaticMarkup` (escaped) and makes no network requests; the find panel's `innerHTML` only receives the app's own icons | CSP still allows inline styles; no HSTS (set it at the reverse proxy) |
| Rogue database server | A user points the app at a server they control (any host the policy allows) and answers with crafted protocol data, or hangs up mid-query | Catalog queries only, results never executed. A connection lost mid-query fails that request only (the pg and mysql2 connections have an `error` listener; a server that hangs up does not stop the process). MySQL (`mysql2`): `disableEval: true` (rows are parsed by its static parser, not by JavaScript generated from the column metadata the server sends, the path of earlier code-injection CVEs); `LOAD DATA LOCAL INFILE` impossible (no `infileStreamFactory`, and the `LOCAL_FILES` capability is not announced: `flags: ['-LOCAL_FILES']`); `multipleStatements` stays off | A server may still ask for a weaker authentication method (for example cleartext) and receive the password the user typed for that very server; with TLS `off` it crosses the network in clear |
| Server CPU | Any signed-in person makes the server parse DBML on demand: a save marked `entry: 'refresh'` compares the stored and the sent text for its history entry, and the parse blocks the event loop (1 vCPU: about 0.2 s at 30 tables, 1.6 s at 200 tables, 5-6 s near the 500 KB cap) | Only people who can edit the diagram (`PUT` refuses view and comment before reading the body); only when a history entry is written (never on a 409 or a save that changes nothing); each text at most 500 KB; at most 6 parses in 10 minutes per person (`agents.withinRate`), then the line summary. An agent's save has the same 500 KB cap plus its per-token rate limit; the scheduled refresh parses as the owner, at the connection's interval (5 minutes at the least) | No general rate limit on `/api/*` (left to the reverse proxy); the parse budget is per person and in memory |
| Supply chain | Vulnerable deps | lockfiles committed; `npm audit --audit-level=high` in CI; actions pinned by SHA; Dependabot. `mysql2` (MIT, 7 dependencies) reviewed for 1.0 | automated audit of advisories only, no review of new releases |

## Pre-deployment checklist (public / multi-user)

What the app does is ticked; what the operator does when hosting it is marked **(operator)** and described in the *Self-hosting* documentation page.

- [x] Authentication (accounts) and per-user ownership of connections and diagrams ([09](09-accounts-sharing.md)).
- [x] Outbound policy for DB hosts (`DB_HOST_POLICY`); the resolved IP is pinned to close the DNS-rebinding window (`public-only`: `assertHostAllowed` returns the address it checked and the drivers connect to it; PostgreSQL TLS still checks the name through `servername`; MySQL and Oracle in TLS *verify* keep the name, because their drivers check the certificate only against the host they connect to, and the certificate check then stops a rebound name). **(operator)** set `public-only` or `allowlist`.
- [x] `APP_SECRET`: the server refuses to start without one when `COOKIE_SECURE=1`, `DB_HOST_POLICY` is not `open` or `REQUIRE_APP_SECRET=1`; a different key after a restore keeps the connection lists working (unreadable secrets are listed as `secretLost` and asked for again). **(operator)** keep it in a secret manager; changing it means typing the connection passwords again.
- [x] The default compose file does not make the app trust the public demo certificate (`docker-compose.demo-tls.yml`, opt-in, tests only).
- [x] Security headers + CSP, sign-in/sign-up throttling. **(operator)** HTTPS termination (reverse proxy + `COOKIE_SECURE=1` / `TRUST_PROXY=1`) and a general rate limit on `/api/*` at the proxy (example in *Self-hosting*).
- [x] Audit log for the use of shared connections, administrator actions, sign-ins and daily backups ([09](09-accounts-sharing.md)).
- [x] Limits on what a request can cost: 30 s per statement and 8 s to connect on every engine, 2 MB of DBML per save (500 KB for an agent and for the structural summary of a refresh), 3 MB per request body, 64 KB per CA certificate. No limit on the size of a catalog.
- [x] Sessions list and revocation, session length and inactivity limit, link expiry, account self-closing (7-day grace), persistent failed-attempt limiter.
- [x] Self-service password recovery without e-mail: a recovery key the person keeps (hash only, single use, rate-limited, audited).
- [x] MCP connector for AI clients ([09](09-accounts-sharing.md)): separate agent accounts created by administrators, bearer tokens (hash only, shown once, expiry, revocation) valid only on `/mcp`, access only through the usual grants, no connection or credential ever returned, text marked as untrusted, every call audited, per-token rate limit, Origin check.
- [x] Password hashing cost: scrypt with Node's default (N = 16384, r = 8, p = 1), below the OWASP minimum (N = 2^17). **Accepted**: N = 2^17 needs 128 MiB per hash, so four sign-ins at once would fill a 512 MB container, and the stored `scrypt$salt$key` has no cost field (a change needs a versioned format and rehash on sign-in). Sign-in budgets (per address, per account) limit guessing instead.
- [x] Dependency scan in CI (`npm audit --audit-level=high` for server and web in `ci.yml`); container runs as non-root (user `node`); read-only filesystem except `/data` and a small `/tmp` (`docker-compose.yml`).
- [x] Privacy: only schema metadata is read, no table data leaves the database (*Introduction* and *Database security* pages).
- Not planned: MFA, SSO, e-mail verification and e-mail password reset (no SMTP); see [00](00-product.md).
