# 15 — Full audit (2026-10-22) and improvement plan

**Status:** proposal, reviewed a second time (Fable 5.1, fresh context, read-only; see *Second review*): the plan below waits for the author's choice of what goes in before the release items 8, 9 and 11 of [14](14-release-v1.md).

## Scope and method

One pass over the whole repository after items 7 and 7b, the performance work and the five manual-validation fixes of the day. Checked: the security invariants of `AGENTS.md` against `server/src/index.js`, `auth.js`, `policy.js`, `audit.js`, `presence.js`, `agents.js`; the catalog queries of `introspect.js`; the web bundle, the parse and layout costs; the UI found while validating by hand; tests, CI and release readiness against the checklist of [14](14-release-v1.md).

Evidence gathered: `npm audit` (server and web: 0 vulnerabilities), `npm outdated`, file sizes, the built `server/public/assets`, a timing of `parse` and `layout` with `web/stressdbml.mjs` at 50 / 100 / 200 tables (Node, no browser), and the browser checks of the fixes of the day.

**Not checked in this pass:** a penetration test against a running instance; Oracle query plans on a large real catalog; a real cloud MySQL or PostgreSQL TLS endpoint; screen-reader use beyond the accessible names; the CI e2e job on GitHub (it has only run on a laptop).

Severity: **High** = a security invariant or data loss; **Medium** = a real risk or a visible defect with a cheap fix; **Low** = polish or a corner case; **Info** = a decision to record, no code.

No High finding in the first pass; the second review found one (M1, operations).

## Second review (Fable 5.1, 2026-10-22)

A reviewer with a fresh context checked every finding in the code (read-only, both unit suites green). Verdicts: S5 and O2 wrong (withdrawn above), S4 refined, the rest confirmed. It also found what the first pass missed; the author checked M1 to M4 in the code before writing them here.

| # | Sev. | Finding | Evidence | Fix |
|---|---|---|---|---|
| M1 | **High** (operations), **done** | The CSRF guard compares the `Origin` host with the raw `Host` header. Behind nginx with its default `proxy_pass` (which sends the upstream name, e.g. `app:3000`, as `Host`) every POST, sign-in included, is refused with 403 "cross-origin request blocked". `TRUST_PROXY=1` does not help: the code reads `req.headers.host`, not Fastify's proxy-aware `req.host`. A self-hoster without support cannot sign in. | `index.js` `onRequest` and `/mcp`; the self-hosting page does not mention `Host` | Compare with `req.host` (it honours `X-Forwarded-Host` when `TRUST_PROXY=1`); one line in *Publishing it* (`proxy_set_header Host $host`); `http.test.js` case with `x-forwarded-host`. |
| M2 | Medium | A changed or lost `APP_SECRET` (a restore on another machine, a rotated `.env`) breaks the whole connection list, not only the secrets: the lists decrypt `ca_pem` of every row for `hasCa`, and a wrong key throws, so `GET /api/connections` and the administrator's list answer 500 and scheduled refreshes fail. | `store.js` `dec`, `list`, `listFor`, `listShared` | A row that cannot be decrypted is listed with `secretLost: true` and empty secrets; the form asks for the password again; `store.test.js`. |
| M3 | Medium | Anyone with an `edit` grant can delete history entries, named versions and "Before agent edit" included, although named versions are documented as never pruned. | `index.js` `DELETE /api/diagrams/:id/versions/:vid` behind `editable`; `diagrams.js` `deleteVersion` | Deleting a version needs owner or administrator (or editors may delete unnamed ones only); `http.test.js`. |
| M4 | Low | Wording: `AGENTS.md` invariant 5 says an administrator never gets the owner's `source`; `getForUser` gives it to anyone who may use the shared connection it points at (connection id, schemas, tables; no secret). | `diagrams.js` `getForUser` | Align the invariant's wording with the code (or strip `source` for `admin`). |
| M5 | Low | `validConn` does not check that `password`, `caPem` and `serverDn` are text: another type reaches the encryption and answers 500. | `index.js` `validConn`, `store.js` | A `typeof` guard; `http.test.js`. |
